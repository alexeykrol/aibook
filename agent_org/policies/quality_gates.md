# Quality Gates

## Gate 1: Product

- Product brief exists and states clear success criteria
- Problem statement is specific and actionable
- Scope is bounded

## Gate 2: Engineering

- Engineering spec exists and maps to the product brief
- Task graph exists and breaks work into concrete work orders
- Dependencies between tasks are identified

## Gate 3: Execution

- Work order exists with clear acceptance criteria
- Status board is updated with current progress
- Handoff log records transitions between pipeline stages

## Gate 4: Review

- Deliverable meets the acceptance criteria from the work order
- Code runs without errors (if applicable)
- No regressions introduced

## Gate 5: Learning

- Evaluation trace documents what went well and what didn't
- Improvement backlog updated if gaps were found
- Pattern library updated if a reusable pattern was discovered
