## 🗺️ Квест 1: «Первый агент»

> *Сложность: ★☆☆ | XP: +40 | Навык: Claude Desktop + MCP, первый рабочий агент без единой строки кода*

### Задание

Запусти **первого рабочего агента** через Claude Desktop с подключённым MCP-сервером. Агент должен сделать что-то реальное с файлами или папками на твоём компьютере.

Цель: почувствовать разницу между «Claude отвечает» и «Claude действует».

### Что тебе нужно

- Claude Desktop (скачай с официального сайта Anthropic: claude.ai/download)
- Node.js — среда выполнения (nodejs.org, бесплатно, простая установка)
- Двадцать минут

Это всё. Без Python, без API-ключей, без программирования.

### Как выполнить

**Шаг 1: Установи Claude Desktop**

Скачай с официального сайта Anthropic и установи как обычное приложение. Войди в свой аккаунт Claude. Убедись, что приложение запускается и работает — можешь поговорить с ним как обычно.

**Шаг 2: Установи Node.js**

Перейди на nodejs.org, скачай версию LTS (рекомендованную). Установи. Это займёт три минуты — просто следуй инструкциям установщика.

**Шаг 3: Добавь MCP-сервер filesystem**

Найди конфигурационный файл Claude Desktop. Его расположение:
- **macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows:** `%APPDATA%\Claude\claude_desktop_config.json`

Открой этот файл в любом текстовом редакторе. Если файл пустой — это нормально. Вставь этот JSON:

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/ТВО_ИМЯ/Downloads"
      ]
    }
  }
}
```

**Замени** `/Users/ТВО_ИМЯ/Downloads` на реальный путь к папке Downloads на твоём компьютере.

На Windows это выглядит как: `C:\\Users\\ТВО_ИМЯ\\Downloads`

Сохрани файл.

**Шаг 4: Перезапусти Claude Desktop**

Полностью закрой приложение и открой снова. В правом нижнем углу окна чата должна появиться иконка — небольшой значок инструментов. Это означает, что MCP-сервер подключён.

**Шаг 5: Дай агенту задачу**

Напиши в Claude Desktop:

> «Посмотри, что находится в моей папке Downloads. Составь список всех файлов с указанием типа (документ, изображение, видео, другое) и размера. Упорядочи по размеру от большего к меньшему.»

Смотри, что происходит. Claude не просто ответит — он откроет папку, просмотрит файлы, составит структурированный список.

**Это и есть агент в действии.**

### Варианты первой задачи

Выбери ту, что ближе к твоей реальности:

**Если ты работаешь с документами:**
> «Найди в папке Downloads все PDF-файлы. Для каждого файла прочитай первые несколько страниц и напиши одно предложение — о чём этот документ.»

**Если тебя беспокоит порядок:**
> «Посмотри на файлы в Downloads. Предложи структуру папок для их организации. Создай эти папки и перенеси файлы по категориям.»

**Если хочешь начать с самого простого:**
> «Посчитай, сколько файлов разных типов в папке Downloads. Выведи статистику: сколько PDF, сколько изображений, сколько других. Какой файл самый старый?»

### Что делать, если не работает

**Иконка инструментов не появилась:** Убедись, что JSON написан без ошибок (запятые, кавычки). Можешь проверить через jsonlint.com — вставь туда свой JSON, он покажет ошибки.

**Claude говорит «не могу получить доступ к файлам»:** Проверь путь к папке в JSON — он должен существовать на твоём компьютере.

**Ошибка «npx не найден»:** Node.js не установился или нужно перезагрузить компьютер после установки.

Если застрял — спроси ChatGPT или Claude.ai: «Помоги настроить MCP filesystem server для Claude Desktop на [macOS / Windows]. Вот ошибка: [скопируй текст ошибки].» Тебе помогут.

### Критерий успеха

- Claude Desktop запущен с подключённым MCP-сервером (видна иконка инструментов)
- Агент выполнил задачу с файлами — не просто описал что делать, а реально сделал
- Ты видел, как Claude использует инструменты (в интерфейсе видны вызовы инструментов)
- Ты можешь описать одним предложением разницу между «Claude отвечает» и «Claude действует»

### 💬 Наставники перед боем

**Мясник:** JSON — это не программирование. Это конфигурационный файл. Как настройки Wi-Fi или параметры в телефоне. Ты вставляешь готовый текст, меняешь один путь к папке. Если запнулся на этом — не называй это «я не умею программировать». Называй это «я не прочитал инструкцию». Прочитай ещё раз.

**Странник:** Интересно вот что: Claude не получил новые знания от подключения MCP. Он получил **руки**. Возможность действовать в реальной среде. Тот же разум — другие возможности. Ты сам становишься другим не от новых знаний, а от новых возможностей действовать?

**Ментор:** Когда Claude выполняет задачу с файлами, обрати внимание на то, что он показывает в интерфейсе — каждый вызов инструмента виден как отдельный блок. Это и есть «шаги агента». Посмотри на них: это план выполнения, который агент строит сам. Один инструмент называется `list_directory`, другой `read_file`. Это анатомия агента в реальном времени.

## 🗺️ Квест 2: «Агент по расписанию»

> *Сложность: ★★☆ | XP: +60 | Навык: n8n + AI-агент, автономная система с расписанием*

### Задание

Создай **агента, который работает по расписанию** — без твоего участия. Агент должен регулярно выполнять полезную задачу и присылать тебе результат.

Не скрипт, который ты запускаешь. Система, которая работает сама.

### Выбери задачу для агента

Выбери одно из трёх — или придумай своё:

**Вариант A: Дайджест новостей**
Каждое утро агент: ищет новости по твоей теме → анализирует → присылает в Telegram краткий дайджест из 5 пунктов.

**Вариант B: Мониторинг сайта**
Раз в день агент: проверяет нужный тебе сайт → ищет изменения или новые публикации → уведомляет, если нашёл что-то интересное.

**Вариант C: Анализ задач**
Каждое утро агент: читает список задач из Google Sheets → приоритизирует через AI → присылает в Telegram «три задачи на сегодня».

### Инструмент: n8n

n8n — визуальный конструктор автоматизаций с поддержкой AI-агентов. Ты строишь агента перетаскиванием блоков.

**Как начать:**
1. Открой n8n.io — есть облачная версия с бесплатным пробным периодом
2. Зарегистрируйся
3. Создай новый Workflow (рабочий процесс)

**Структура агента в n8n:**

```
[Триггер] → [AI Agent] → [Инструменты] → [Действие]
```

Для Варианта A:
```
[Расписание: каждый день в 8:00] → [AI Agent] → [Поиск в интернете] → [Telegram: отправить сообщение]
```

### Как выполнить

**Шаг 1: Создай Telegram-бот для уведомлений**

Это займёт три минуты:
- Найди в Telegram бота `@BotFather`
- Напиши ему `/newbot`
- Следуй инструкциям — придумай имя и username для бота
- BotFather выдаст тебе **Token** — сохрани его

Потом узнай свой `Chat ID`:
- Напиши своему новому боту любое сообщение
- Открой в браузере: `https://api.telegram.org/bot[ТВОЙ_TOKEN]/getUpdates`
- Найди в ответе `"chat":{"id":` — это и есть твой Chat ID

**Шаг 2: Добавь нужные учётные данные в n8n**

В n8n перейди в Credentials (учётные данные) → добавь:
- Telegram API Token (от BotFather)
- OpenAI или Anthropic API ключ (для AI-агента)

Если хочешь использовать поиск — добавь SerpAPI (есть бесплатный уровень).

**Шаг 3: Собери Workflow**

Добавь блоки по порядку:

1. **Trigger: Schedule** — настрой расписание. Для начала поставь «каждые 5 минут» — чтобы быстро протестировать.

2. **AI Agent** — выбери модель. Напиши системный промпт:

Для Варианта A:
> «Ты — ежедневный дайджест-агент. Твоя задача: найти 5 актуальных новостей по теме [ТВОЯ ТЕМА]. Для каждой новости: заголовок, одно предложение о чём это, почему это важно. Формат: короткий список, дружелюбный тон, без лишних слов.»

3. **Tool: HTTP Request или SerpAPI** — добавь инструмент поиска к агенту.

4. **Telegram: Send Message** — настрой отправку результата тебе.

**Шаг 4: Протестируй вручную**

Нажми «Test Workflow» — n8n запустит весь процесс прямо сейчас. Проверь: агент нашёл новости? Telegram получил сообщение?

Если что-то не так — посмотри в логах каждого блока, где остановилось. n8n показывает входящие и исходящие данные каждого шага.

**Шаг 5: Активируй**

Когда тест прошёл успешно — переключи расписание на нужное тебе время (например, `0 8 * * *` означает каждый день в 8:00) и активируй Workflow.

Теперь агент работает сам.

### Отладка без паники

**Агент не находит информацию:** Проверь, подключён ли инструмент поиска. Без поиска агент работает только со знаниями из обучения.

**Telegram не получает сообщение:** Убедись, что Chat ID правильный. Попробуй написать боту что-нибудь ещё и снова получи Chat ID через `getUpdates`.

**Непонятный формат ответа:** Добавь в системный промпт конкретный пример формата, который хочешь видеть.

### Критерий успеха

- Workflow создан и активирован
- Агент отработал хотя бы один раз — ты получил сообщение в Telegram
- Workflow запускается по расписанию без твоего участия
- Ты можешь изменить промпт агента и увидеть изменение в результате

### 💬 Наставники перед боем

**Мясник:** Первый раз не получится с первого раза. Это нормально — не значит, что ты не справляешься. Значит, ты отлаживаешь. Каждый программист, каждый инженер, каждый автоматизатор проходит через «что-то пошло не так, надо разобраться». Разница между теми, кто строит, и теми, кто не строит — только в том, останавливаются ли они на первой ошибке.

**Странник:** У тебя теперь есть агент, который думает и действует, пока ты спишь. Это не метафора — это буквально происходит в 8 утра по расписанию, без тебя. Как это меняет твоё ощущение от рабочего утра? От того, что значит «начать день»?

**Ментор:** Если хочешь сделать Workflow надёжнее — добавь блок обработки ошибок. В n8n это называется «Error Workflow»: отдельный сценарий, который запускается, если основной упал. Самый простой вариант — тот же Telegram с сообщением «Агент упал, проверь». Так ты всегда знаешь, когда что-то пошло не так.

## 🗺️ Квест 3: «Команда агентов»

> *Сложность: ★★★ | XP: +80 | Навык: Многоагентная система — от архитектуры к работающей команде*

### Задание

Спроектируй и запусти **многоагентную систему** для решения реальной задачи. Система состоит из нескольких агентов с разными ролями, которые работают вместе.

Это не упражнение «как это устроено». Это реальная задача, которая тебе полезна.

### Что такое многоагентная система — на пальцах

Представь, что ты нанял небольшую команду для одного проекта:
- Исследователь: собирает информацию
- Аналитик: обрабатывает и структурирует
- Автор: пишет финальный текст или отчёт
- Менеджер: координирует всех, следит за результатом

В многоагентной системе каждую роль выполняет AI-агент. Они передают результаты друг другу по цепочке. Ты ставишь задачу менеджеру — и получаешь готовый результат.

### Выбери задачу для команды

Используй задачу из своей реальной работы или жизни. Хорошая задача для многоагентной системы — это сложная, многошаговая задача, которую ты сейчас делаешь сам и которая занимает несколько часов.

**Примеры:**

**Еженедельный отчёт по отрасли:**
Исследователь → собирает новости и данные
Аналитик → выделяет тренды и значимые события
Редактор → форматирует в читаемый отчёт
*Результат: PDF-документ или Google Doc раз в неделю*

**Анализ конкурентов:**
Сборщик → находит актуальную информацию о конкурентах
Аналитик → сравнивает по ключевым параметрам
Стратег → формулирует выводы и рекомендации
*Результат: сравнительная таблица + текстовые выводы*

**Система создания контента:**
Исследователь → находит актуальные темы
Автор → пишет черновик поста
Редактор → правит под стиль и платформу
*Результат: готовые посты для публикации*

**Персональный аналитик:**
Сборщик → читает твою почту или задачи за день
Приоритизатор → ранжирует по важности
Планировщик → составляет план дня с объяснениями
*Результат: утренний план в Telegram*

### Инструмент: CrewAI с Cursor

CrewAI — Python-фреймворк для многоагентных систем. Cursor напишет весь код за тебя по твоему описанию.

Если ты уже знаком с n8n — многоагентную систему можно собрать и там, используя несколько последовательных AI Agent блоков.

### Как выполнить

**Шаг 1: Спроектируй архитектуру на бумаге**

Прежде чем открывать любой инструмент — нарисуй схему на листе бумаги или в любом текстовом файле.

Ответь на вопросы:
1. Какую задачу решает система?
2. Какие роли нужны? (не больше трёх-четырёх для начала)
3. Что делает каждый агент — конкретно?
4. В каком порядке они работают?
5. Где система получает входные данные?
6. Каким должен быть финальный результат?

Пример архитектуры для еженедельного отчёта:
```
Вход: тема отрасли (например, "финтех в России")
↓
Агент 1: Исследователь
- Инструменты: поиск в интернете
- Задача: найти 10 значимых материалов за последние 7 дней
- Вывод: список URL с кратким описанием
↓
Агент 2: Аналитик
- Инструменты: читает список от Исследователя
- Задача: выделить 3 главных тренда, ранжировать по важности
- Вывод: структурированный анализ
↓
Агент 3: Редактор
- Инструменты: файловая система (создать документ)
- Задача: написать отчёт в читаемом формате для нетехнической аудитории
- Вывод: готовый текстовый документ
↓
Выход: файл report_YYYY-MM-DD.md
```

**Шаг 2: Опиши архитектуру в Cursor**

Открой Cursor. Создай новый проект. В чате опиши систему:

> «Создай многоагентную систему на CrewAI. Мне нужна команда из трёх агентов для [ОПИШИ ЗАДАЧУ].
>
> Агент 1: [роль, что делает, инструменты]
> Агент 2: [роль, что делает, инструменты]
> Агент 3: [роль, что делает, инструменты]
>
> Агенты работают последовательно. Вход: [что]. Выход: [что].
>
> Используй CrewAI, SearchTools для поиска. Сделай запускаемый скрипт main.py.»

Cursor создаст все необходимые файлы: `main.py`, `agents.py`, `tasks.py`, `requirements.txt`.

**Шаг 3: Установи зависимости**

В терминале Cursor:
```bash
pip install crewai crewai-tools
```

Если Cursor предложит установить сам — соглашайся.

**Шаг 4: Добавь API-ключи**

Создай файл `.env` в папке проекта:
```
OPENAI_API_KEY=твой_ключ
SERPER_API_KEY=твой_ключ  # для поиска, если используешь
```

Попроси Cursor: «Добавь загрузку переменных из .env файла через python-dotenv.»

**Шаг 5: Запусти и итерируй**

Запусти: `python main.py`

Первый запуск почти наверняка покажет ошибку — это нормально. Скопируй текст ошибки в чат Cursor: «Вот ошибка: [текст]. Исправь.»

Обычно требуется два-три цикла «запустил → ошибка → исправил» прежде чем система заработает полностью.

Когда система отработает первый раз — посмотри на результат. Дай обратную связь каждому агенту через промпт: что сделал хорошо, что нужно изменить. Проси Cursor переписать промпты.

### Оценка результата

После того как система сработала, задай себе эти вопросы:

**О качестве:**
Результат достаточно хороший для реального использования? Или нужно улучшить промпты?

**О времени:**
Сколько времени заняло бы сделать это вручную? Насколько система ускорила процесс?

**О надёжности:**
